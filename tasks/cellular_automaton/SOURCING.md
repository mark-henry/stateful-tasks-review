# SOURCING — cellular_automaton

Task as assigned: elementary 1-D cellular automaton on a small ring (width default 8), rule number
as a knob, one line per step showing the bitstring, answer = bitstring after `depth` steps.
Cited: Rule 90 linear over GF(2) (shortcuttable); Rule 110 P-complete (Neary & Woods 2006);
Liu et al. 2022 "Transformers Learn Shortcuts to Automata" (arXiv:2210.10749).

## Candidates vendored

### `vendor/shortcut_automata/` — ClaraBing/shortcut_automata (GitHub, commit `60e8c76`)
This is the **project website** for Liu, Ash, Goel, Krishnamurthy, Zhang, "Transformers Learn
Shortcuts to Automata" (arXiv:2210.10749, ICLR 2023 workshop / TMLR). It contains only
`index.html`, CSS, and figure images — **no code, no generator, no released dataset**. The paper's
empirical section does train Transformers to simulate CAs (including elementary 1-D rules) and
finite-state automata, but the authors did not publish the training-data generator or eval harness
alongside this repo, and no separate code repo could be located via GitHub/PapersWithCode search.
No LICENSE file is present (site content only; treat as all-rights-reserved for anything beyond
citation).
- Contains: nothing usable for the common interface. Value is citation + theory framing only
  (motivates the depth/rule knobs and the "shortcut" framing in desk.json's theory_class).
- Distance from common interface: N/A, no code.
- What would be missing if used: everything — generator, solver, prompt format, step lines.

### `vendor/rule110_span_long/` — N8Programs/rule110_span_long (HuggingFace dataset, license cc0-1.0)
Raw newline-delimited bitstrings (long, non-uniform-width lines), apparently spans generated by
running Rule 110 for some number of steps, intended as an LM-pretraining corpus. Only a 5KB sample
(`sample_train.txt`) was kept, not the full multi-MB file. No README beyond a license stub, no
generator script, no metadata (ring width, boundary condition, seed, step count are all unstated
and cannot be reliably reverse-engineered), no prompt/answer framing.
- Contains: raw CA output only. No generator, no reference solver, no rigid step-line format, no
  per-instance metadata.
- Distance from common interface: far. Would need width/rule/boundary reverse-engineered (unreliable)
  or discarded entirely in favor of a fresh generator.
- What would be missing: `generate()`, `solve()`, `Instance` fields, step formatting — essentially
  the whole interface.

## Candidates found and rejected (not vendored)
- `neoneye/simon-cellular-automaton-v15` / `-v16` (HuggingFace) — 2-D image-to-text CA dataset
  (Game of Life / HighLife / Serviettes / Cave / Maze variants, RLE-encoded images, ARC-AGI style).
  Wrong dimensionality (2-D grids, not a 1-D ring), wrong modality (image-to-text, not text
  bitstrings), and step count is fixed at 1-2, so it can't express a `depth` knob. Not vendored.
- `qizwiz/rule110-church-numerals` (HuggingFace) — a small, non-rigorous "research" dataset
  claiming a "mod-5 hypothesis" linking Church numerals to Rule 110 "echo patterns"; contains no
  actual CA simulation trace, just hand-written classification labels. Not usable and not vendored.
- Misc toy GitHub repos implementing Rule 110 for visualization (`jacksonthall22/Rule-110`,
  `rogue-agent1/cellular-automaton-py`, `pjwmascall/rule-110`, `TheAbstract/rule110`,
  `LiterallyLegendary/infinite-rule-110-py`) — single-purpose scripts/notebooks for plotting CA
  evolution, no LM-facing prompt/answer format, no per-step state serialization matching the spec's
  rigid-line requirement, no differential solver. Not vendored (low value over writing ~20 lines of
  bit-shift logic from scratch; the rule-application logic itself is one line of Python
  (`new[i] = (rule >> ((left<<2)|(cell<<1)|right)) & 1`), so there is nothing substantial to reuse).

## Recommendation
**Nothing usable — must write.** No candidate provides a generator, reference solver, or
scratchpad/answer format anywhere close to the common interface. The core CA transition rule is
also trivial to implement correctly and independently-verify (rule as an 8-bit lookup table indexed
by the 3-cell neighborhood, applied on a width-8 ring), so there is no procurement value in forcing
a fit to the vendored HF dataset or the toy GitHub scripts. `shortcut_automata` is kept only for its
citation/theory value (Rule 90 linearity, Rule 110 P-completeness per Neary & Woods 2006, and the
Liu et al. 2022 "shortcut" framing) to be referenced in the eventual README, not as source material
to wrap.
