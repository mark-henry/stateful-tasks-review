bug from a Python-version drift since the repo was written; our driver script monkey-patched
random.sample at call time to sort the set into a list first. No other logic was changed.

--- step-by-step (direct=False / "cot") format, as decoded by the repo's own decode() ---
ST₀_₃T₁_₀T₂_₀T₃_₃T₄_₂ X₅X₉X₁X₅X₇X₈ X₉X₇X₅X₉X₃X₂ X₉X₇X₅X₉X₃X₂ X₉X₇X₅X₉X₃X₂ X₇X₉X₅X₇X₀X₃ X₈X₇X₄X₈X₆X₁

Structure: "S" (start token) + one T_d subscript task-token per depth level naming which of
{identity, function 1, function 2, function 3} was applied at that depth (here: T0_3 T1_0 T2_0
T3_3 T4_2) + a space + the initial length-6 vector of alphabet tokens (X5 X9 X1 X5 X7 X8, each
Xi drawn from a 10-symbol alphabet) + one space-separated length-6 vector PER depth step showing
the result of applying that step's function to every position of the vector in parallel (5
depth steps here, matching function.depth=5).

--- direct (direct=True / no-CoT) format, for contrast, same run ---
ST₀_₀T₁_₃T₂_₁T₃_₃T₄_₀ X₈X₃X₆X₃X₃X₆ X₉X₀X₆X₀X₀X₆

Structure: same task-token header, then only the initial vector and the FINAL composed vector
(no intermediate depth-by-depth outputs) -- this is the paper's natural "no-CoT" contrast prompt.
