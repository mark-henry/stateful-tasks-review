## Knobs

- **addition**: digits / integer, per-digit (operand width) / tokens flat: N
- **affine_mod_p**: depth (number of sequential affine-map compositions applied to the state) / integer, step size 1, no natural ceiling; a secondary knob is the modulus p (integer >= 2, task as scoped uses small p such as 7 or 11) / tokens flat: ·
- **blocksworld**: blocks (number of blocks in the domain) / integer, paper sweeps 3-20 (Figure 2); depth (plan length in actions) is a secondary knob, not separately scored here / tokens flat: N
- **boolean_expressions**: nesting depth / operator count / integer; canonical BBH examples use roughly 4-8 operators. google/BIG-bench's task.py generator (SOURCING.md candidate) exposes expression_lengths directly, tuple-valued, 1-14 (complexity exponential in length) / tokens flat: ·
- **cellular_automaton**: depth / integer step count (secondary knobs: rule in 0-255, an 8-bit lookup table; width, the ring size, default 8) / tokens flat: ·
- **cruxeval**: executed-line / trace-length count of the sampled function (not a generator parameter -- the published dataset of 800 code/input/output triples is fixed; 'depth' would have to be an emergent bucketing of which fixed instance is sampled) / per-instance (discrete, dictated by the natural line-count distribution of the fixed 800-row dataset, not chosen by us) / tokens flat: ·
- **cup_shuffling**: n (number of people/objects) / 1, fixed to {3,5,7} in the published BBH subtasks / tokens flat: N
- **dyck**: prefix length, k (number of bracket types), max stack depth / integer for all three; canonical BBH prefixes run roughly 3-20 symbols with k up to 4 types ((), [], {}, <>); the vendored princeton-nlp/dyck-transformer generator (SOURCING.md candidate 3) exposes k and max_stack_depth directly as constructor arguments / tokens flat: N
- **entity_tracking_boxes**: numops (number of operations affecting the queried box) / 1, evaluated over 0-7+ in the paper's Figure 2/5, with a fixed 12-operation scenario length by default / tokens flat: ·
- **grid_navigation**: number of instructions (trace depth) and per-instruction step/turn magnitude / integer instruction count; canonical BBH examples run roughly 2-10 instructions with single- or double-digit step magnitudes / tokens flat: ·
- **hanoi**: disks (N) / integer, paper tested a range up to N=12 (N>12 excluded for context-length reasons per Appendix A.1) / tokens flat: Y
- **khop_pointer_chasing**: depth (number of hops) / integer >=1; because f is fixed and shown once, an alternate solution strategy's true cost scales as O(log depth) rather than O(depth), so depth is a weaker difficulty knob here than in the other two tasks even though naive single-hop CoT length still grows linearly with it / tokens flat: ·
- **last_letter_concat**: depth (number of words) / 1 / tokens flat: Y
- **modn_counter**: N (cyclic group order / modulus) and T (sequence length, i.e. depth/number of moves) / N: integer group order -- Liu et al.'s main experiments test C2 through C8 (Appendix B.1.1); the independently-vendored BeeGass/Group-Dataset-Generator generator confirms the same construction extended up to C30. T: integer sequence length -- Liu et al.'s main experiments fix T=100 (chosen so |Sigma|^100 sequences are far larger than the training sample budget, ruling out memorization). / tokens flat: ·
- **multiplication**: digits (per-operand digit count, via the vendored generator's --num_digit sweep; can be set independently for x and y, typically driven symmetrically for depth-scaling) / integer digit-count per operand (1, 2, 3, ...); numbered-step count grows as digits_y * (digits_x + 1), plus one unnumbered final summation paragraph / tokens flat: N
- **nested_arithmetic**: nesting depth / innermost chain length (BIG-bench generator's depth_level_list x length; BBH's fixed multistep_arithmetic_two set uses depth_level_list=[2,2], i.e. two nested two-way splits, with 3-4 single-digit operands per innermost group) / integer levels for nesting depth; integer operator count for innermost chain length; operand magnitude fixed at single digits [-9,9] in the published fixed set / tokens flat: N
- **parity_coinflip**: depth (number of people/flip events) / 1 / tokens flat: ·
- **random_lookup_table**: function.depth (repo config/gen/conf.yaml) / integer >=1; tokens per step-vector stay flat across depth (each step prints one fixed-length seq_len vector), total prompt length grows linearly with depth / tokens flat: Y
- **river_crossing_checkers**: N (checkers per side / actor-agent pairs) / integer, N>=1 / tokens flat: N
- **s5_composition**: depth (called story_length in the repo's CLI, --story-length) / integer >=1; repo CLI default is 100 for actual training corpora, this trace uses 8 for a short readable example / tokens flat: Y
- **synthetic_program_trace**: depth / 1 executed statement; loop iterations are fully unrolled into separate line/state pairs (Nye et al.'s own convention -- Figure 1's caption: 'all loops are unrolled across time') / tokens flat: ·
- **threesum**: length (n, number of input tuples; dimension and mod held fixed at 3 and 10) / integer, n>=6 (get_true_instance/get_corrupted_instance need 3 slots for the planted triple plus room for at least 3 noise tuples) / tokens flat: N
- **turing_machine**: depth / integer step count; default tape_length=6 cells (binary alphabet), default num_states=3 / tokens flat: Y
- **web_of_lies**: depth (chain length / number of people) / 1 / tokens flat: Y
